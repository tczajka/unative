# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Crate overview

`unative` is a `no_std` Rust library that exposes two platform-native integer types: [UNative](src/unative.rs) (unsigned) and [INative](src/inative.rs) (signed). Both always have the same width, chosen at compile time to be the widest size for which the target has efficient hardware arithmetic (including multiplication and division). This is often, but not always, the same as `usize` — e.g. on `x86_64-unknown-linux-gnux32`, `usize` is 32 bits but `UNative` is 64 bits.

MSRV is 1.95 (edition 2024). The MSRV must be kept in sync between `Cargo.toml`'s `rust-version` and the `msrv` CI job in [.github/workflows/ci.yml](.github/workflows/ci.yml).

## Architecture

The public types are thin `#[repr(transparent)]` newtypes around a primitive integer (`u16/u32/u64` or `i16/i32/i64`). Which primitive is chosen lives in [src/inner.rs](src/inner.rs), which uses `cfg_select!` to pick `bits16`, `bits32`, or `bits64`. Note that `x86_64` and `aarch64` are forced to 64-bit even on 32-bit-pointer ABIs (x32, ILP32) because their hardware still supports efficient 64-bit ops.

The bulk of the surface area is generated by macros in [src/native.rs](src/native.rs). The `define_native!` macro emits the entire inherent-method API (constants, bit ops, checked/overflowing/saturating/wrapping/strict/unchecked/unbounded arithmetic, byte conversions, `from_str_radix`, etc.) plus all operator/`From`/`TryFrom`/`Sum`/`Product`/`Display`/etc. trait impls, by delegating to the inner primitive's methods. Helper macros (`delegate_binop!`, `delegate_shifts_*`, `delegate_from_*`, `delegate_try_from_*`, `delegate_fmt!`, …) cover the various owned/borrowed argument permutations.

`unative.rs` and `inative.rs` each invoke `define_native!` once, then add the methods that are specific to unsigned or signed integers (e.g. `UNative::next_power_of_two`, `INative::abs`) and the per-type `From`/`TryFrom` conversions.

When adding new methods, follow the existing pattern: add the delegating method (or a new macro variant) in `native.rs` if it exists on both types, otherwise add it to `unative.rs` or `inative.rs`. Keep doc comments and `#[inline]`, and prefer `const fn` matching the underlying primitive's signature.

## Commands

- Build: `cargo build`
- Test (host): `cargo test`
- Run a single test: `cargo test --test unative <test_name>` or `cargo test --test inative <test_name>`
- Format check: `cargo fmt --check`
- Clippy (CI gate — must be warning-free): `cargo clippy --all-targets -- -D warnings`
- 32-bit test (matches CI): `cargo test --target i686-unknown-linux-gnu` (requires `gcc-multilib`)
- 16-bit build check (matches CI, needs nightly): `cargo build --lib --target msp430-none-elf -Z build-std=core`
